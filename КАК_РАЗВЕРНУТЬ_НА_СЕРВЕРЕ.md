# Как развернуть бота на сервере (чтобы он работал без вашего компьютера)

Зачем: сейчас бот живёт на вашем Mac и засыпает вместе с ним. На сервере он отвечает
круглосуточно — Mac можно выключать, спать, уезжать.

**Что уже готово в репозитории:** `Dockerfile`, `Procfile`, `railway.json`,
`docker-compose.yml`, `app/scheduler.py` (бот сам обновляет данные из CRM и сам шлёт
еженедельный отчёт). Нужен только хостинг и перенос ключей.

---

## Что нужно от вас (2 шага, оба в браузере)

1. **Залогиниться/зарегистрироваться на хостинге** (Railway — самый простой, VPS — дешевле).
2. **Вписать ключи в Variables** — это 6 строк, они ниже.

Ключи лежат в файле `.env` на вашем Mac
(`~/Documents/Codex/Dance/dance-attendance/.env`). Он **никогда** не попадает в Git.

| Переменная | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен вашего бота от @BotFather |
| `TELEGRAM_ALLOWED_USER_IDS` | ваш Telegram ID (числом), чтобы отвечал только вам |
| `IMPULSE_BASE_URL` | адрес CRM студии |
| `IMPULSE_API_KEY` | ключ пользователя «Аналитик-бот» (или `IMPULSE_LOGIN` + `IMPULSE_PASSWORD`) |
| `DATABASE_URL` | строка подключения к облачной базе (Supabase, session pooler) |
| `LLM_API_KEY`, `LLM_FOLDER_ID`, `LLM_PROVIDER`, `LLM_MODEL` | доступ к ИИ для комментариев и вопросов |

---

## Путь 1. Railway — всё в браузере, ~10 минут

Railway сейчас **не принимает новые регистрации** (после инцидента 21.10; статус
на [status.railway.com](https://status.railway.com), открытие пока без даты).

**Как только откроют** — два варианта.

### Вариант А: я делаю всё сам, вы только входите в браузере

На вашем Mac уже установлен Railway CLI. Когда откроется регистрация, я запускаю
`bash scripts/railway_up.sh`: скрипт создаст проект, перенесёт все ключи из `.env`
в Variables (значения идут через stdin — не попадают ни в историю команд, ни в
список процессов) и задеплоит бота.

От вас будет **одно действие**: в открывшейся ссылке войти через GitHub
(или ввести код из консоли, если браузер не откроется сам).

### Вариант Б: всё руками в панели Railway

1. [railway.app](https://railway.app) → **Login** → войти через GitHub.
2. **New Project** → **Deploy from GitHub Repo** → выбрать `aliviyaaaaa/dance-attendance`.
3. Railway сам соберёт контейнер по `Dockerfile`. Тип сервиса — **Worker**
   (по `Procfile` бот не должен завершаться).
4. **Variables** → **Raw Variables** → вставить 6 строк из таблицы выше
   (по одной на строку, `ИМЯ=значение`).
5. **Deploy** → открыть вкладку **Logs** — должно быть
   `Бот @garage_spb_analytics_bot запущен` и `Расписание включено`.
6. Написать боту в Telegram `/status` — он ответит, когда следующее обновление.

### Нюанс: на Railway нет постоянного диска

Файлы контейнера при перезапуске обнуляются, поэтому локальная база SQLite
каждый раз заполняется заново из CRM (12 недель, 1–3 минуты). Это не поломка:
рабочая база восстанавливается автоматически, а постоянное хранилище —
облачный Postgres, оттуда читает дашборд. Если захотите ускорить старт —
подключите Railway Volume (это платно).

## Путь 2. VPS — дешевле и доступно сегодня

Подойдёт любой VPS: Timeweb Cloud, Aéza, reg.ru, Selectel — от 150–300 ₽/мес за
самый маленький (1 ядро, 1 ГБ, достаточно для бота).

1. Зарегистрироваться и создать сервер: **Ubuntu 22.04**, тариф подешевле, регион СПб/Финляндия.
2. В панели открыть **веб-консоль** (Console / VNC) и вставить по очереди:

```bash
apt update && apt install -y git docker.io docker-compose-v2
mkdir -p /opt/garage && cd /opt/garage
git clone https://github.com/aliviyaaaaa/dance-attendance.git
cd dance-attendance
```

3. Создать файл с ключами (в веб-консоли — редактор `nano .env`):

```bash
nano .env
```

Вставить содержимое вашего `.env` с Mac (все строки, включая комментарии — они не мешают),
сохранить: `Ctrl+O`, `Enter`, `Ctrl+X`.

4. Запустить бота:

```bash
docker compose up -d && docker compose logs -f
```

Должно появиться `Бот @garage_spb_analytics_bot запущен` и `Расписание включено`.
`Ctrl+C` выходит из журнала — контейнер продолжит работать.

5. Проверить в Telegram: `/status`.

> Если в консоли написано, что команды `docker compose` нет, поставьте плагин:
> `apt install -y docker-compose-plugin` (или используйте `docker-compose` вместо `docker compose`).

---

## Важно: не запустить два бота с одним токеном

Telegram не допускает двух опросников с одним токеном — они будут мешать друг другу.
После того как серверный бот отвечает в Telegram, **выключите бота на Mac**:

```bash
launchctl bootout gui/$(id -u)/local.garage.attendance
```

Вернуть на Mac (если сервер решите выключить):

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.garage.attendance.plist
```

## Пока сервера нет — временная мера на Mac

Чтобы бот не засыпал вместе с компьютером (нужны права администратора):

```bash
sudo pmset -a sleep 0
```

Вернуть как было: `sudo pmset -a sleep 1`.
Это не «агент без вас»: компьютер всё равно нужно держать включённым.

## Что бот делает сам на сервере

| Когда | Что |
|---|---|
| каждый день в 06:00 МСК | выгружает свежие данные из CRM и обновляет облачную базу |
| каждый понедельник в 09:00 МСК | присылает отчёт за прошлую неделю (текст + Excel) |
| при перезапуске | доливает историю, если база пустая, и обновляет протухшие данные |
| по команде `/status` | показывает свежесть данных и расписание |

Расписание настраивается переменными `SYNC_HOUR`, `REPORT_WEEKDAY`, `REPORT_HOUR` —
см. `.env.example`.

## Если что-то пошло не так

- **Бот молчит** → смотрите журнал: `docker compose logs -f` (VPS) или вкладка Logs (Railway).
- **Ошибка входа в CRM** → проверьте, что в Variables именно `IMPULSE_API_KEY`
  (или логин с паролем) и что ключ не протух.
- **Нет данных за неделю** → в первые минуты после запуска сервер догружает историю
  (12 недель), это 1–3 минуты.
- **Postgres недоступен** → бот продолжит работать на локальной базе, в логе будет
  предупреждение. Данные в облако тогда не попадут.
