Готово. Supabase подключён, бот пишет в базу, данные переживают перезапуск.

**Что сделано**

- Создан проект Supabase `garage-analytics` (Garage Studio, Free), регион eu-west-1.
- Строка подключения лежит только в `.env` проекта как `DATABASE_URL` — в коде её нет,
  в GitHub она не попадала ни разу (`.env` в `.gitignore`).
- Бот пишет в Postgres сам: после обновления данных из CRM и после каждого отчёта.
- Данные читаются из базы, а не из памяти процесса.

**Какие таблицы** (все в схеме `public`, их видно в Table Editor):

| Таблица | Что внутри | Сейчас строк |
|---|---|---|
| `studio_groups` | группы студии: направление, педагог, вместимость | 41 |
| `group_week_stats` | показатели группы за неделю + статус (просела / растёт / под наблюдением) | 1373 |
| `attendance_daily` | посещаемость и записи по дням и группам | 2531 |
| `studio_meta` | служебное: какой день загружен, когда обновляли | 1 |
| `dashboard_groups`, `dashboard_daily` | готовые представления для дашборда | — |

**Что перезапускал и сколько раз**

Перезапускал **Telegram-бота** (служба `local.garage.attendance` на macOS, он же
автозапуск). За сегодня — **4 перезапуска**: 00:47, 00:55, 14:04, 14:21.

После каждого данные на месте. Последняя проверка: в 14:20 опубликовал свежий снимок
из CRM (данные по 23.10), в 14:21 перезапустил бота, после перезапуска в базе
на месте: 41 группа, 1373 строки недельных показателей, 2531 строка посещаемости по
дням, 14 626 отметок, последний загруженный день — 23.10.

**Скриншот** — Table Editor после перезапуска, в списке слева все 6 таблиц,
открыта `attendance_daily` с 2 531 записями.

**Про безопасность.** В проекте включён «Enable automatic RLS», поэтому у новых таблиц
Row Level Security включается автоматически. Проверил прямо в базе: под ролью `anon`
(анонимный ключ проекта, которым пользуется публичный Data API) таблицы отдают
**0 строк**, под ролью `postgres` — все данные. То есть из публичного API данные
студии не читаются, читает только бот.

**Честно про ограничения**

- Railway изначально был невозможен: у них глобально отключена регистрация новых
  аккаунтов после инцидента 21 октября. Supabase выбрал как замену — тот же Postgres,
  код к провайдеру не привязан, при открытии регистрации в Railway переезд = одна
  строка в `.env`.
- Прямое подключение Supabase идёт по IPv6, у этой сети нет маршрута IPv6 — использую
  session pooler.
- Данные обновляются только когда бот обновляется из CRM (кнопка `/refresh` в Telegram
  или еженедельный отчёт). Автообновления по расписанию пока нет.
- База в облаке Supabase, сам бот по-прежнему работает на моём Mac — это отдельный
  следующий шаг.
